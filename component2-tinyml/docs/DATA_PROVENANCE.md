## 5. Collection structure

- **Unit of collection:** an experiment *run*, identified by `run_id` = `<site>-<class code>-<NN>` (e.g. `SITE-A-NOR-07`). Codes: NOR, PAR, DUS, OPE, SHO.
- **Run length:** 60 readings at 5 s intervals (295 s per run).
- **Totals:** 100 runs = 20 per class; 6000 readings = 1200 per class.
- **Sites/devices:** 6 (`SITE-A`…`SITE-F`, `ESP32-A01`…`ESP32-F01`, `PV-A01`…`PV-F01`).
- **Windows:** `TRAINING` (10 runs per class) and `OPERATION` (10 runs per class), following the group data contract timeline.

Runs per site and class:

| Site | NORMAL | PARTIAL_SHADING | DUST | OPEN_CIRCUIT | SHORT_CIRCUIT | Total |
|---|---|---|---|---|---|---|
| SITE-A | 6 | 10 | 2 | 1 | 2 | 21 |
| SITE-B | 5 | 0 | 6 | 2 | 1 | 14 |
| SITE-C | 3 | 0 | 1 | 8 | 5 | 17 |
| SITE-D | 2 | 7 | 3 | 0 | 4 | 16 |
| SITE-E | 4 | 2 | 7 | 5 | 8 | 26 |
| SITE-F | 0 | 1 | 1 | 4 | 0 | 6 |

Four sites do not cover every class. This limits leave-one-site-out evaluation (`ARCHITECTURE.md` §8.1).

- No duplicate `record_id` values and no duplicate device/timestamp pairs.

## 7. Validation results (from `results/dataset_validation.md`)

### 7.1 Summary
**Result: PASS with 4 warnings, 0 errors.**

| Check | Result |
|---|---|
| Required columns (column contract) | all present; no unknown columns |
| Labels | all 5 present, 1200 rows each |
| Missing values / sensor error codes | none |
| Duplicates | none |
| Run consistency (label, site, device, window per run) | consistent in all 100 runs |
| Timestamp order and 5 s spacing | correct in all runs |
| Physical ranges | all values within the documented limits |
| Power consistency (P = V × I) | max deviation 0.084 mW (rounding) |
| Per-class files vs combined file | 5/5 exact copies |
| Prediction file | rejected as ground truth; 72.07% agreement with labels; OPERATION rows only |

### 7.2 Warnings
1. `irradiance_lux` is at the 100,000 lx saturation value in 76 rows.
2. `health_score` alone predicts the label with 74.6% run-wise accuracy (chance ≈ 20%).
3. `run_id` contains the class code.
4. Sites missing classes: SITE-B, SITE-C (PARTIAL_SHADING), SITE-D (OPEN_CIRCUIT), SITE-F (NORMAL, SHORT_CIRCUIT).

### 7.3 Consequences for Component 2
- `health_score`, `run_id`, `record_id`, `window` and `site_id` are **never model inputs** (`contract.py`).
- Splits are **run-wise** only. Readings within a run are near-identical, so random row splits would leak.
- Only `pv_fault_dataset.csv` is used for training and evaluation.

## 8. Known sensor limitations

| Limitation | Evidence | Effect on Component 2 |
|---|---|---|
| Lux values above 65,535 lx (1,283 rows); 76 rows at exactly 100,000 lx | validation report | if the lux sensor is a BH1750 (max 65,535 lx), values above that cannot come from it directly. Saturated readings make irradiance-normalised features unreliable → `SKIPPED_LUX_SATURATED` (`ARCHITECTURE.md` §5) |
| Lux → irradiance uses a fixed factor (lux / 120) | group data contract | approximation; spectrum- and sensor-dependent |
| Sensor models, ADC resolution, calibration undocumented | no firmware in the repository | feature thresholds and saturation limits are placeholders |
| Panel datasheet values are marked "ASSUMED" | `panel_datasheet.csv` (component 4) | physical range limits in `validate.py` are approximate |
| No wind sensor | group data contract | not used by Component 2 |

Observations from the validation that the evidence above should explain:
- All intra-run intervals are exactly 5 s, all 100 runs start at second :00, and every run has exactly 60 readings.
- Four pairs of runs on different sites overlap in time (e.g. `SITE-C-SHO-11` and `SITE-E-OPE-03` at 2026-09-07 05:27 UTC). This requires more than one panel/device operating at the same time.
- The data comes from 6 sites/devices.
- `sites.csv` contains per-site class-mix columns (`mix_normal` … `mix_short_circuit`) and placeholder coordinates.
- The group data contract (`665de11`) contains a section on how the shared data was made. It must be reconciled with Member 1's statement.

Until this is resolved, results obtained with this dataset are reported as results **on the PV sensor dataset provided by Member 1**, without further claims about its acquisition.
